# 수어 인식 → 문장 생성 구조

수어번역 대화 앱(iOS)에서 청인 폰 카메라가 농인의 수어를 보고 한국어 문장을 만들기까지의 과정을 정리한 자료다.
수치는 직접 측정한 값이고, 측정 환경을 함께 적었다.

---

## 1. 한눈에 보는 전체 흐름

```
 [카메라 30fps]
      │  청인 아이폰 후면 카메라, 세로 1280×720
      ▼
 ① 관절 추출 ── MediaPipe Holistic: 몸·양손·얼굴 랜드마크
      ▼
 ② 89점 변환 ── 학습 데이터(OpenPose) 배치에 맞춤: 상체 13 + 왼손 21 + 오른손 21 + 얼굴 34
      ▼
 ③ 떨림 보정 ── One-Euro 필터
      ▼
 ④ 정규화 ──── 목을 원점으로, 어깨너비를 1로
      ▼
 ⑤ 단어 구간 자르기 ── 손 움직임 에너지로 "단어 시작 → 끝" 판정
      ▼
 ⑥ 특징 만들기 ── 64프레임으로 보간 + 프레임 간 속도 → 64 × 356
      ▼
 ⑦ 단어 분류 ── Conv-Transformer 모델(ONNX) → 1,200개 단어 확률
      ▼
 ⑧ 단어 확정 ── 같은 단어 확률 합산, 확신도 50% 이상만 채택, 너무 짧은 구간 제외
      ▼
 ⑨ 문장 모으기 ── 1.5초 동안 손을 멈추면 "문장 끝"
      ▼
 ⑩ 문장 생성 ── 규칙 기반 조사·어미 결합: [사과, 달다] → "사과가 달아요"
      ▼
 [청인 화면 표시 + 농인 폰으로 전송]
```

모든 단계가 **아이폰 안에서** 돌아간다. 영상과 관절 좌표는 저장하지 않고 폰 밖으로 보내지 않는다. 두 폰 사이에는 완성된 텍스트만 오간다.

## 2. 단계별 설명

### ① 관절 추출 — MediaPipe Holistic
- 영상 한 프레임에서 몸(33점), 양손(각 21점), 얼굴(478점)의 위치를 찾는다.
- 옵션은 PC 실험과 같게 맞췄다: 몸 검출 신뢰도 0.5, 손 랜드마크 신뢰도 0.3, 비디오 모드.

### ② 89점 변환 — 학습 데이터 형식에 맞추기
- 모델은 AI Hub 수어 데이터(OpenPose 형식)로 학습했다. 앱은 MediaPipe를 쓰므로 점 번호 체계가 다르다.
- 수어에 필요한 부분만 남겨 **89점**으로 맞춘다.

| 부위 | 점 수 | 내용 |
|---|---|---|
| 상체 | 13 | 코, 목, 어깨·팔꿈치·손목(좌우), 골반 중앙, 눈·귀(좌우) |
| 왼손 / 오른손 | 21 / 21 | 손목 + 손가락 마디 (두 형식이 같은 21점 구조) |
| 얼굴 | 34 | 눈썹 10, 눈 12, 입 12. 수어의 문법 표지인 표정 정보 |

- 목은 MediaPipe에 없어서 양 어깨의 중점으로 만든다. 얼굴 34점은 FaceMesh 영역에서 고르게 뽑은 **근사치**다.

### ③ 떨림 보정 — One-Euro 필터
- MediaPipe 좌표는 프레임마다 미세하게 흔들린다.
- 가만히 있을 때는 강하게 누르고, 빠르게 움직일 때는 반응을 살리는 **적응형 저역통과 필터**를 쓴다(min_cutoff 1.2, beta 0.3).

### ④ 정규화 — 사람·거리·위치 차이 없애기
- 모든 점에서 **목 좌표를 빼고(원점 이동)**, **어깨너비로 나눈다(크기 통일)**.
- 카메라와의 거리나 화면 속 위치가 달라도 같은 수어는 같은 값이 된다.
- 어깨가 안 잡히는 프레임은 마지막 정상값을 쓰고, 시작 직후 한 번도 못 잡았으면 그 프레임은 건너뛴다. 좌표가 폭발하는 버그를 막기 위한 처리다.

### ⑤ 단어 구간 자르기 — 손 움직임 에너지
- 연속 영상에서 "어디부터 어디까지가 한 단어인가"를 정해야 한다.
- 매 프레임 **양손 42점의 평균 이동량(에너지)**을 계산하고, 상태 머신으로 판정한다.

```
 대기 ──(에너지 > 0.06)──▶ 녹화 중 ──(에너지 < 0.03 이 10프레임 지속, 또는 90프레임 도달)──▶ 단어 끝
```

- 끝에 붙은 정지 프레임은 잘라 낸다.

### ⑥ 특징 만들기 — 64 × 356
- 길이가 제각각인 구간을 **64프레임으로 선형 보간**한다.
- 각 프레임 = 위치 178개(89점 × x,y) + **속도** 178개(직전 프레임과의 차이) = **356차원**.
- 너무 튀는 값은 ±20(어깨너비 20배)으로 자른다.

### ⑦ 단어 분류 — Conv-Transformer
| 층 | 역할 |
|---|---|
| Linear 356 → 160 | 입력 압축 |
| Depthwise Separable Conv × 3 (커널 5) | 짧은 시간 범위의 움직임 패턴 |
| 위치 인코딩 + Transformer 인코더 × 3 (헤드 4) | 동작 전체의 순서·관계 |
| 시간 평균 → Linear 160 → 1200 | 1,200개 단어 점수 |

- 파라미터 **약 126만 개, 5.6MB**. PyTorch 모델을 **ONNX로 변환**해 아이폰에서 ONNX Runtime으로 실행한다.
- 변환 검증: 클립 200개에서 원본과 1순위 단어 **200/200 일치**, 출력 오차 최대 0.0000076.

### ⑧ 단어 확정
- softmax로 확률을 구한 뒤 **같은 한글 단어의 확률을 합친다**. 1,200개 클래스 중 같은 단어가 여러 번 등록된 경우가 있어 고유 단어는 1,166개다.
- **확신도 50% 이상**인 1순위만 단어로 채택하고, 미만이면 버리고 "다시 해 주세요"를 표시한다.
- **20프레임(약 0.7초) 미만** 구간은 판정하지 않는다. 손을 내리는 동작이 단어로 잡히는 것을 막기 위해 실측으로 정한 값이다.
- (시연용 옵션) **상황 어휘 모드**: 지정한 단어 몇 개만 후보로 보는 모드. 예를 들어 보건소 상황에서는 "감기, 진단서, …"만 본다.

### ⑨ 문장 모으기
- 단어가 하나씩 들어오다가 **45프레임(약 1.5초) 동안 손이 멈추면** 문장이 끝난 것으로 본다.
- 단어 사이의 짧은 쉼(10프레임)과 문장 사이의 긴 쉼(45프레임)을 다른 기준으로 구분한다.

### ⑩ 문장 생성 — 규칙 기반 조사·어미 결합
한국수어는 조사와 어미가 거의 없는 언어라서, 인식 결과는 **"핵심어 나열"**이다(예: 사과, 달다). 이를 자연스러운 한국어로 바꾸는 단계다.

1. **품사 판별:** 각 단어가 명사인지 동사·형용사인지 구분한다.
2. **술어 결정:** 마지막 동사·형용사를 술어로 삼는다. 없으면 "-하다"를 붙이거나("근무" → "근무해요") 서술격 "-이에요"를 붙인다.
3. **조사 결정:** 명사의 부류 × 술어의 종류로 정한다.

| 명사 부류 | 술어 종류 | 조사 | 예 |
|---|---|---|---|
| 사람(맨 앞) | 무엇이든 | 은/는 | **나는** 식당에 가요 |
| 장소 | 이동·존재 | 에 | 식당**에** 가요 |
| 장소 | 그 밖의 동작 | 에서 | 식당**에서** 근무해요 |
| 사물 | 타동사 | 을/를 | 커피**를** 싫어해요 |
| 사물 | 형용사·자동사 | 이/가 | 사과**가** 달아요 |
| 같은 부류 연속 | — | 와/과 | 커피**와** 콜라를 싫어해요 |

4. **시제·어미:** "아까, 방금, 이미, 어젯밤" 같은 단어가 있으면 과거형으로 바꾼다(예: [아까, 사과, 달다] → "아까 사과가 달았어요"). 어미는 해요체(-어요)가 기본이고 합쇼체(-습니다)도 고를 수 있다.
5. **받침에 따른 형태:** 은/는, 이/가, 을/를, 활용형(달다 → 달아요, 가다 → 가요)을 맞춘다.

**앱 구현 방식:** 원래는 Python 형태소 분석기(Kiwi)가 필요하지만 아이폰에서는 쓸 수 없다. 그래서 인식 가능한 단어가 1,200개로 정해져 있다는 점을 이용해, **PC에서 Kiwi로 1,200단어의 품사·조사 결합형·활용형을 미리 계산한 표(0.6MB)**를 앱에 넣었다. 앱은 표를 찾아 이어 붙이기만 하므로 오프라인에서 즉시 동작한다.

**예시 (실제 앱 출력)**
| 인식된 단어 | 생성 문장 |
|---|---|
| 사과, 달다 | 사과가 달아요 |
| 커피, 싫어하다 | 커피를 싫어해요 |
| 나, 식당, 가다 | 나는 식당에 가요 |
| 진단서 | 진단서예요 |

**한계:** "감기에 걸리다"처럼 단어 부류만으로 알 수 없는 **관용 표현**이나 원인 관계("감기로")는 틀린다. 예를 들어 [손자, 감기]는 "손자가 감기에 걸렸어요"가 아니라 "손자는 감기예요"가 된다.

## 3. 검증과 측정 결과

### PC 원본과의 일치 (자동 테스트)
| 항목 | 결과 |
|---|---|
| 전처리(②~⑥) Swift 이식 | Python 원본과 오차 0.0001 미만, 실시간 스트림 410프레임 구간 판정 100% 일치 |
| 모델 변환(⑦) | 1순위 단어 200/200 일치 |
| 문장 생성(⑩) | 평가 문장 130개, 무작위 단어 조합 1,000개 모두 Python 원본과 같은 문장 |

### 원본 모델·문장 규칙 성능 (PC, AI Hub 데이터)
| 항목 | 결과 |
|---|---|
| 단어 인식 정확도 (학습에 없던 수어사 기준) | **top-1 98.0%** (1,200단어) |
| 문장 생성 정답률 | 개발 문장 37/40, 나중에 쓴 문장 21/25 |

### 아이폰 실측 (iPhone 14 Pro, 2026-11-01)
| 항목 | 결과 |
|---|---|
| 카메라 처리 속도 | **30fps** 유지 |
| 단어 1개 판정 (구간 → 특징 → 모델) | **6~10ms** (모델만 1.8ms) |
| 시연 단어 인식 (학습 수어 동작을 보고 연습한 뒤) | 사과 53%, 달다 63~74%, 커피 57%, 감기 58~97%, 진단서 94~97% |

### 확인된 과제
- **학습 환경과 실제 환경의 차이:** 학습 데이터는 스튜디오에서 OpenPose로 추출했고, 앱은 폰 카메라와 MediaPipe를 쓴다. 노트북 웹캠 실측에서 1순위 확신도 중앙값은 16%였다.
- **수어자에 따른 차이:** 같은 단어라도 동작이 학습 수어사와 다르면 다른 단어로 인식된다. 학습 데이터의 동작을 보고 맞춰 연습하면 인식률이 크게 올라갔다(사과: 상위 후보 밖 → 53%).
- **어휘 1,200개:** "먹다", "있다", "병원" 같은 기본어가 없다.

## 4. 참고한 자료

### 데이터
- **AI Hub 「수어 영상」 데이터셋** (한국지능정보사회진흥원, NIA): 단어 수어 영상의 OpenPose 2D 키포인트(BODY_25, 손 21×2, 얼굴 70). 수어사 16명 × 1,200단어 × 카메라 5방향 = 96,000 클립으로 학습했다.

### 관절 추출·형식
- **MediaPipe Holistic** (Google): Lugaresi et al., "MediaPipe: A Framework for Building Perception Pipelines", 2019. 앱은 MediaPipe Tasks iOS의 `HolisticLandmarker`를 쓴다.
- **OpenPose**: Cao et al., "OpenPose: Realtime Multi-Person 2D Pose Estimation Using Part Affinity Fields", IEEE TPAMI, 2019. 학습 데이터의 키포인트 형식이다.

### 전처리
- **One-Euro 필터**: Casiez, Roussel, Vogel, "1€ Filter: A Simple Speed-based Low-pass Filter for Noisy Input in Interactive Systems", CHI 2012.

### 모델 구조
- **Transformer**: Vaswani et al., "Attention Is All You Need", NeurIPS 2017.
- **Depthwise Separable Convolution**: Howard et al., "MobileNets: Efficient Convolutional Neural Networks for Mobile Vision Applications", 2017.
- (비교 실험, 채택 안 함) **ST-GCN**: Yan et al., "Spatial Temporal Graph Convolutional Networks for Skeleton-Based Action Recognition", AAAI 2018. **본(bone) 특징**: Shi et al., "Two-Stream Adaptive Graph Convolutional Networks for Skeleton-Based Action Recognition" (2s-AGCN), CVPR 2019.

### 문장 생성
- **Kiwi 한국어 형태소 분석기** (kiwipiepy, github.com/bab2min/Kiwi): 품사 태깅과 형태소 결합(조사 이형태·활용). PC에서 결과 표를 만드는 데 사용했다.

### 앱 실행 환경
- **ONNX Runtime** (Microsoft): 아이폰에서 모델 실행.
- **Apple Speech `SpeechAnalyzer`** (iOS 26): 청인 음성의 온디바이스 한국어 인식.
- **Apple MultipeerConnectivity**: 두 아이폰 연결(블루투스·기기 간 와이파이).
